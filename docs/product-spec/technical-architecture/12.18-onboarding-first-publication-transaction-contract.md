# 12.18 — First publication transaction foundation — LOCKED

This bounded database contract follows pinned O01-S6, FR-IDN/FR-PRD/FR-RES,
OD-PUB-003/005 and 12.13–12.16. It preserves one explicit final user-level intent
and truthful per-record publication. All prepared public records reside in one
Postgres database, so this implementation commits the selected bundle atomically.
Any failure leaves every Working/Draft record and public state unchanged.

Supported prepared bundles are Identity only and Identity + Resource. Product
publication is explicitly unavailable until its mandatory renderable primary
image and structured marketplace-destination model exist. Title + safe URL do
not satisfy FR-PRD-004/009. Selected Profile Media also blocks Identity publication
until its separate public transport is ready; it is never silently omitted.
Unselected/invalid optional Drafts remain private and recoverable.

Publish receives the current Owner's opaque receipt UUID, acknowledged digest
and explicit bundle (`identity_only`, `product`, `resource`). The receipt is the
idempotency identity for this one first-publication operation, not an arbitrary
Owner selector. Lock Owner, then progress, receipt, saved content, reservations,
and relevant safety rows in deterministic hash order. Re-read the current S6
snapshot, reject mismatched/superseded/expired receipts and changed revisions,
then repeat exact URL/hash safe/unexpired checks using wall-clock time after
locks. Waiting for a lock cannot make an expired verdict eligible.

One private Identity publication row records the exact acknowledged saved
Identity/layout/Connection snapshot. An optional Item publication records the
existing immutable Item identity/reference and Resource snapshot. A composite
foreign key binds Item/Owner/type/reference to its permanent reservation. Private
tables have RLS and no Data API role grants. Public readers must later construct
minimal DTOs from these snapshots and current account/lifecycle/safety state,
never raw Working or private receipt rows.

One first-publication receipt per Owner records immutable result metadata,
selected bundle, digest and receipt UUID. Replaying exactly the same successful
intent returns the original authoritative acknowledgment even after review TTL;
a changed bundle/digest/UUID returns `conflicting_intent`. Current account
restriction still takes precedence over replay. A completed Owner with no matching
first-publication record is rejected rather than synthesized. No duplicate Item,
reference or publication is allocated on retry.

Only successful atomic persistence sets Owner onboarding completion and advances
progress revision. Publication success includes Identity/Item status separately;
Identity-only reports no Item publication. It changes no saved content revision.
Failed validation, stale review, exhausted revision or transaction error cannot
complete onboarding, delete Drafts or silently fall back to Identity-only.

This migration intentionally withholds authenticated RPC execution until the
public-read/workspace/UI transport contract is implemented and verified. Tests
grant execution only inside their rolled-back fixture transaction. No production
first-Publish button or endpoint access is enabled by this database checkpoint.
Public Profile Media, Product publication, returning-owner lifecycle and full
S6 closure remain open. Future enabling requires public snapshot routing,
safe click transport, explicit bundle review and universal workspace handoff.
