### Canonical transactional database

- PostgreSQL is canonical truth.
- Supabase Postgres is the managed provider.
- Free during development/small usage when suitable; Pro and larger compute/disk/read replicas/PITR as measured need grows.
- All database changes are versioned SQL migrations in Git.
- Production schema is not managed by undocumented dashboard-only edits.
- Local/CI database is reproducible from migrations + controlled fixtures.

Logical schema families:

```text
auth          provider-managed authentication identities
core          private canonical Owner/Identity/Spill domain data
publication   public-safe Published projections
analytics     product-owned events and aggregates
moderation    reports/cases/evidence/enforcement/appeals
audit         append-only accountability events
ops           protected platform/operator controls
api           explicitly exposed safe views/RPC when justified
```

Do not place all application data into one broadly exposed schema.

### Authentication

- Supabase Auth.
- Email/password + Google OAuth for MVP.
- Authentication is separate from authorization.
- Spall Spill maintains stable application Owner identity separately from provider identity.
- Operators/moderators/admin-capability users require MFA before protected operator use.
- High-risk actions may require fresh strong authentication, not merely any valid old session.

### Authorization / tenancy

Defense in depth:

```text
server/application authorization
+
PostgreSQL grants/RLS where applicable
```

Rules:

- deny by default;
- IDs and URLs never grant authority;
- cross-owner forged reads/writes fail;
- private Draft/Working/Hidden data never leaks through public APIs;
- public discovery resolves Published/public-safe projections only;
- operator capability is explicit and server-derived;
- RLS/grant policies receive allow and deny tests in CI.

### Working / Published isolation

Conceptual publication contract:

```text
Working revision N
  ↓ publish exact revision N
authorization + validation + moderation/account checks
  ↓
Published projection N
```

Saving Working state never silently updates Published state.

### Concurrency

Authoritative conflicting writes use revision preconditions:

```text
write(baseRevision = N)
only if authoritative revision == N
→ commit N + 1
```

Stale writes return `STALE_WRITE` and never overwrite newer authority or regress because responses arrive out of order.

### Object/media storage

- Cloudflare R2.
- Binary objects live outside PostgreSQL.
- S3-compatible provider boundary.
- Logical trust classes are separated, e.g. public media, private evidence, backups, temporary uploads.
- Privileged R2 credentials never enter browser code.
- Browser uploads use short-lived constrained presigned URLs after trusted server authorization.
- Validate size, magic bytes/actual MIME, decodability, dimensions, ownership, intended content class, and unsafe metadata policy.
- Do not accept arbitrary raw user SVG by default.
- Protected evidence/backups remain private.

### DNS / abuse protection

- Cloudflare DNS.
- Cloudflare Turnstile on abuse-prone unauthenticated writes/auth flows.
- Turnstile must be verified server-side; client widget success is not authorization.
- Upstash Redis for distributed action-specific rate limits across serverless instances.
- Rate-limit keys may combine IP, user, Owner, action, and abuse context.

### Search

Phase 1:

- exact Handle resolution;
- exact Spill Reference resolution;
- canonical/legacy Spall URL resolution;
- PostgreSQL full-text search;
- trigram/similarity/index techniques where justified.

Exact identifier resolution precedes fuzzy discovery. If search later needs a dedicated engine, it is a rebuildable projection; PostgreSQL remains canonical truth.

### Background work

- Supabase Queues / pgmq for initial durable queueing.
- Supabase Cron / pg_cron for scheduled work.
- Workers are idempotent.
- Authoritative workflows never rely on unreliable fire-and-forget HTTP side effects.
- Use a transactional outbox when an authoritative database mutation must cause async external work.

Example:

```text
publish exact revision
+ Published projection
+ Audit event
+ Outbox event
COMMIT
→ worker performs retryable external/index/email work
```

### Transactional email

- Resend.
- SPF/DKIM/DMARC for the sending domain.
- Provider behind a notification adapter.
- No provider-specific email payload is product/domain truth.

### Analytics

Creator-visible/business analytics is owned by Spall Spill, including view/click/activation aggregates. Third-party analytics is not canonical creator truth.

- PostHog is optional internal telemetry for product adoption/funnels/experiments/privacy-approved diagnostics.
- If analytics volume later exceeds healthy PostgreSQL boundaries, analytical events/projections may move to a specialized store without changing the transactional domain model.

### Observability

- OpenTelemetry is the instrumentation standard.
- Sentry is the initial error/performance backend.
- Structured logs use correlation identifiers and semantic error codes.
- Never log/send by default passwords, tokens, authorization headers, privileged cookies, service keys, raw sensitive evidence, or unnecessary private form data.

## Web/API security baseline

### Security headers

Production responses explicitly manage:

- Content-Security-Policy;
- Strict-Transport-Security;
- X-Content-Type-Options;
- Referrer-Policy;
- Permissions-Policy;
- CSP `frame-ancestors`.

### XSS

- render user input as data, not executable HTML;
- no arbitrary-user `dangerouslySetInnerHTML`;
- strict URL parsing/normalization;
- CSP limits executable origins;
- active upload formats are restricted/sanitized.

### CSRF / request origin

- state changes do not use GET;
- validate trusted session;
- apply Origin/Host validation and suitable CSRF controls where cookie/session behavior requires it;
- secure SameSite/Secure cookie posture.

### IDOR

Opaque IDs are not authorization. Every private object read/write is scoped by trusted authorization and/or tested database policy.

### Open redirects

Do not implement generic arbitrary `?url=` redirects. Outbound marketplace/resource navigation resolves stored validated destination records and safe protocols, normally HTTPS. Reject `javascript:`, `data:`, `file:` and unsupported schemes.

### SSRF — mandatory

Marketplace/provider metadata fetching must defend against SSRF:

- allowed schemes;
- normalized provider/host;
- loopback/private/link-local/metadata targets blocked;
- DNS/IP checks appropriate to runtime;
- redirect ceiling and revalidation after redirects;
- response-size ceiling;
- timeout;
- provider adapters/allowlists where possible;
- no user-directed arbitrary internal network access.

### Secrets

Never expose privileged Supabase, R2, Resend, Turnstile, Upstash, Sentry management, or deployment credentials through browser/public environment variables.

## Audit

- append-only application paths;
- normal roles cannot update/delete historical Audit events;
- protected authoritative mutations write durable Audit atomically with protected DB mutation where possible;
- sensitive evidence disclosure follows durable-accountability-before-disclosure;
- reversals/corrections are new events;
- Audit is data-minimized and not a secret/raw-log dump.

## Environment separation

```text
LOCAL
→ PREVIEW / DEV

```

## Backup / recovery

At serious public production, provider-managed backups are enabled at the appropriate tier. Also maintain independent PostgreSQL logical backups.

Conceptually:

```text
PostgreSQL logical dump
→ compress/encrypt where appropriate
→ private R2 backup bucket
→ retention policy
```

Backups are periodically restored into fresh non-production data stores and integrity/smoke checks are run. RPO/RTO are defined before public launch and tightened as business criticality grows.

## Performance / scale

Public pages use cacheable Published projections so viral traffic does not force an equivalent expensive database query for every view.

Track at minimum:

- LCP, INP, CLS;
- public response p95;
- owner action/API p95;
- DB query latency;
- error rate;
- queue depth/age;
- worker failure rate.

Not day-one requirements:

- Kubernetes/EKS;
- Kafka;
- Snowflake;
- OpenSearch;
- ClickHouse;
- large Redis clusters;
- service mesh;
- multi-region writable database;
- premature microservices.

Introduce specialized infrastructure only after measured need, behind existing boundaries.
