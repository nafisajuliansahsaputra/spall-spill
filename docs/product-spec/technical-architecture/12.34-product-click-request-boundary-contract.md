## Request gate

Accept only POST JSON requests to a configured canonical HTTPS origin. Configuration
is an exact serialized origin, never inferred from Host/Forwarded headers. Require
exact Origin header, matching request URL origin, no URL credentials/query/fragment,
and matching Host when present. Reject non-same-origin Sec-Fetch-Site when present,
unsupported content encoding, non-JSON media type or malformed/oversized declared
length. JSON supports optional UTF-8 charset only. Maximum body is 4,096 bytes.

Inject one action-specific permit dependency for server-selected issue/redeem.
Await literal true only, within five seconds. Errors, missing/nonboolean responses
or timeout deny; no permissive or process-memory fallback, retry, IP/header trust,
credential or provider activation. The later adapter MUST use distributed limits
and trusted deployment client identity; passing this injected gate is not evidence
that those production protections exist. Origin headers are not authentication.

Only after preflight/permit, read the body stream within five seconds and stop at
4,096 actual bytes regardless of declared length and at most 4,097 read attempts
(including completion) to bound empty-chunk framing. Require declared/actual equality
when provided, strict UTF-8 and valid JSON. Deny on abortion, stream/decode/parse
error, timeout or empty/null JSON. Cancel failed reads without blocking on cancel.
Return unknown JSON only; future assembly MUST validate strict existing locator/
opaque-token context schemas before any core/store call. Parsing is not authority.

Provide fresh no-store headers and a generic JSON unavailable response with no
Location, CORS or private error detail. Future transport MUST apply these headers
to every successful/failed response; a helper alone is not end-to-end cache proof.
