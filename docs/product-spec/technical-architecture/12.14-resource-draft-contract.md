# 12.14 — First Resource Draft

LOCKED scoped implementation contract for O01-S5. Authority: pinned 7.6,
9.10-D06, 11.22, O01/J3/J4 and contracts 12.12–12.13. This contract does not
close S5 or S6 or authorize public publication.

The Owner explicitly chooses one semantic type: menu, price list, catalog,
portfolio, media kit/rate card, document/PDF, website/external resource, or other.
A URL host, extension, provider, or scanner never chooses or changes that meaning.
Meaning plus a nonempty title or ordinary HTTP(S) source is the meaningful private
Draft threshold. Type alone allocates nothing. Title and source may individually
be incomplete; later publication requires recognizable content and a valid source.
Cover and category are optional. This slice supports one external source, not upload.

One first onboarding Resource Draft is retained per canonical Owner independently
of Product Draft and Primary Use Case. Persona guidance never removes capability.
Business presents Resource first; other recommendations offer it optionally and
open a saved Draft. Selecting another semantic Resource type edits content without
converting its immutable Resource Item identity into Product or allocating again.

`core.resource_drafts` is private, RLS enabled, with no Data API table privileges.
Authenticated RPCs derive Owner through `auth.uid()` and verify the S5 prerequisites
using the shared Relevant First Job resolver. Owner and progress locks serialize
saves against content edits and S5 advancement. Independent nullable base revision
means no acknowledged Draft; stale writes fail without changing content or consuming
a Spill Reference. Item creation and the 12.13 permanent reservation commit together.
Reads and invalid input never create Drafts. Revision uses JavaScript-safe integers.

Saving never advances progress, completes onboarding, publishes, certifies a URL,
or fetches content in the database. The web action normalizes sources through the
shared destination policy before RPC and only registers/scans an acknowledged source
after commit. Scanner failures retain a private Draft and fail closed; current exact
source safety must be evaluated afresh at any future publication boundary.

Resolver success returns only current step and Resource type/source/title/revision.
No Owner-selecting argument, reference allocator, public Item lookup, or delete API
is exposed. Content removal retains permanent identity reservations.

Local evidence (2026-10-05): 891 pgTAP tests, 458 Vitest tests, 17 native auth
tests and five tooling tests pass; lint/typecheck/three builds pass. Schema lint
and error-level security advisors pass. Real concurrent Resource-first saves
plus Product creation preserve exactly two references and reject a stale save.
The migration was applied additively to the preserved development database after
a private backup; existing Product content and reservations remain untouched.

An isolated browser Owner traversed S1–S5, rejected an empty Resource shell,
retained the selected type after validation failure, saved title-only content,

Resource remained open with the same reference and revision 2; safety was pending.
