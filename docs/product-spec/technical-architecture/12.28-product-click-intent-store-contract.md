# 12.28 — Withheld durable Product click-intent store — LOCKED

This bounded private persistence dependency follows J2/J4/J6/J9, pinned P03 and
12.26–12.27. It implements the durable store required by the intent core, not

## Private hashed-token persistence

Add a private `core.product_click_intents` table keyed by lowercase SHA-256 token
hash. Store only the strict 12.27 purpose/binding/confirmation_hash/issued_at/
expires_at record, never a raw opaque token, destination URL or Owner/Item UUID.
Validate all keys, JSON types, canonical Handle, positive safe reference, bounded
provider, lowercase publication/destination/confirmation hashes and safe integer
epoch milliseconds. Require exactly 120,000ms lifetime. Enable RLS without public
policies and revoke all table/helper/RPC access from public/anon/authenticated/
service_role. The stored record remains server-only, not a public DTO.

`api.create_product_click_intent_server(hash, record)` returns boolean. Require
strict valid input, database wall-clock time >= issue time and < expiry, and a
fresh successful exact 12.26 binding resolution before insert. Create atomically
with no overwrite on collision, including expired collisions. Database clock is
authoritative and no future-time grace enlarges the lifetime. Server/database
clock alignment and the concrete application RPC adapter remain future gates.

`api.consume_product_click_intent_server(hash)` atomically deletes and returns
one still-current strict record, otherwise SQL null. Expired/future-invalid records
are burned too; no replay or failure restoration. The future adapter must commit
this RPC transaction before any asynchronous destination/outbound decision and
must never wrap consume plus later failure in a rollback that restores authority.
Competing workers produce at most one record. Consuming a record is not outbound
permission: the core still validates context/expiry and re-resolves current safety.

`api.cleanup_product_click_intents_server(limit)` deletes at most 1–500 expired
records by indexed expiry order, with row locks/SKIP LOCKED for parallel workers.
Return deletion count; invalid limit returns zero. Delete no unexpired record.
No schedule/provider is enabled here; before transport activation, bounded cleanup
must be wired and evidenced so abandoned intents cannot accumulate indefinitely.
