# 12.17 — Account status and current-session exit — LOCKED

This bounded foundation follows 12.5/12.7, pinned OD-SEC-002 and D10 9.18.
It repairs the missing destination already used by the authoritative resolver.
It does not implement enforcement-case disclosure, appeal or all D10 workflows.

`/dashboard/account-status` is a private conditional account-level notice. The
server re-verifies current Owner state; only restricted or suspended Owners see
the notice. Missing Owner/failed resolution fails closed; unauthenticated users
go directly to Login; incomplete active Owners go to onboarding and completed
active Owners to the workspace. No Owner target or reason is accepted from URL.
Current state text distinguishes restriction and suspension, explains that
normal workspace/publication access is blocked, and preserves content/lifecycle
history. No detection detail, reports, inferred reason or fabricated appeal
eligibility is displayed. Detailed enforcement/review actions remain open.

Sign Out is an explicit same-origin Next.js Server Action using the request-scoped
Supabase SSR client and `auth.signOut({ scope: 'local' })`. This ends the current
browser/device context only and does not claim to revoke every device or cancel
already issued access tokens globally. No logout mutation is performed by GET.
After provider success, clear normal intended navigation and redirect directly
to `/login`. Provider errors show failure truth with a retry action; never show
logout success or erase navigation intent merely because the request was sent.
Repeat Sign Out when already signed out remains safe under provider semantics.

The restricted account notice exposes only safe session exit. Normal workspace
and publication authorization remain data-layer account-state checks. Sign Out
does not delete Owner/Working/Draft/receipt records or change enforcement state.
