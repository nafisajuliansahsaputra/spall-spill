## Database and storage authority

`api.resolve_published_identity_media_server(handle)` is service-role-only.
It accepts a normalized public Handle/alias, never an Owner, asset or object key.
It independently checks active Owner, completed onboarding, current canonical
Handle and Published Identity lifecycle. The exact snapshot-selected asset must
be finalized canonical same-Owner WebP with bounded bytes/dimensions. No image,
missing/foreign/unfinalized asset, unpublished/hidden/archived/restricted Owner,
invalid Handle and unavailable state all resolve uniformly unavailable.

The service DTO contains only canonical object metadata and an exact publication
token for server use. No browser-facing endpoint exposes the DTO, object key,
asset UUID, privileged key, provider error or signed storage credential.
Private table grants remain absent; the existing server-only elevated client and
bucket-scoped R2 configuration are reused. This is a new narrow public-projection
resolver, not the authenticated upload orchestration described by 12.11.

## HTTP and revocation boundary

`GET /media/identity/{handle}` is a technical image transport, not a new journey
screen. It requires no viewer account and does not refresh viewer sessions.
Only the authoritative resolver may select an R2 object. Download the bounded
canonical object server-side with a deadline and validate its MIME, declared and
actual size, RIFF/WebP framing and namespace. Never follow a caller storage URL,
return a presigned redirect or return staging bytes. Original image sanitization
remains the authoritative decode/metadata-stripping gate in 12.11.

After download, resolve the publication again and compare the complete exact DTO.
An intervening restriction, hide/archive, media replacement or publication change
must deny delivery. A missing credential/provider object, malformed DTO, timeout,
oversize, invalid bytes or failed recheck yields the same generic 404, without
leaking provider payloads. This prevents a stale successful download from granting
continued authorization; lifecycle changes after the final check cannot revoke
bytes already delivered to a viewer.

Serve bytes as `image/webp` with `nosniff`, same-origin resource policy, restrictive
image-response CSP and no-store browser/CDN caching. Ignore conditional/range
requests rather than returning a cached authorization/304 shortcut. Production
cache design, invalidation, edge abuse/rate limits and load verification remain
launch gates; this conservative staged transport does not claim viral readiness.

## Evidence and enabling gates

Tests must prove Published/Working isolation, protected aliases, same-Owner and
consumed-asset checks, uniform visibility denial, private privileges and withheld
publication/reader grants. HTTP/storage tests must prove bounded streaming,
credential/error nondisclosure, no arbitrary object selection, byte validation,
post-download revocation and no-store behavior. Run application quality gates,
database reset/lint/pgTAP and exact-commit CI/Security/Guard.

Live R2 delivery, browser/runtime revocation and provider configuration evidence
remain open until actually observed. This contract alone does not remove the
existing Profile Media publication/read pending gates or close S5/S6.
